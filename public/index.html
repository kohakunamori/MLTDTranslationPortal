    设置

    所有凭据只存在这台浏览器的 localStorage 里，不会发给任何服务器：页面本身是纯静态的。

    GitHub Token（单行修改用）

    填入一个只勾选目标翻译仓库 Contents: Read and write 的 fine-grained token， 就能在阅读页直接改一行译文并提交。留空则整站只读。

    ① 一键新建 Token 或：用经典 Token（勾好权限）

    不会建 Token？点开看 4 步（含权限怎么勾）
    1. 点上面的「① 一键新建 Token」，打开 GitHub 的细粒度 Token 页面。
    2. Token name 随便填；Expiration 选 90 days； Repository access 选 Only select repositories → 勾选 目标翻译仓库。
    3. Permissions → Repository permissions → 找到 Contents → 改成 Read and write（Metadata 会自动跟着变 Read-only，正常）。
    4. 点 Generate token，复制出现的 github_pat_…（只显示这一次）， 回到上面的输入框粘贴 → 保存 → 验证。

    嫌麻烦可以走另一条：经典 Token 链接已经预勾好 public_repo， 点 Generate 复制即可；代价是它对你名下所有公开仓库都有读写权限，而细粒度 Token 只给一个仓库。

    Token 只存在这台浏览器的 localStorage，只发给 api.github.com； 不要贴进聊天或别的网站。怀疑泄露就去 tokens 列表 Revoke 掉重开一个。 完整排错对照表见仓库里的 docs/GITHUB-TOKEN.md。

    AI 草稿（可选）

    自带 endpoint 与 key，浏览器直连服务商；只用来生成草稿，不会自动提交。

    数据来源

    数据由本仓 GitHub Actions 生成；刚提交的改动会在下次生成后出现在页面里。

    怎么用

    • 概览页按 domain / 分类进入；点歌曲卡片或资源行打开日中对照阅读。
    • 大资源被上游切成了多个数据页：阅读页顶部可以翻页，地址形如 #read?file=bundles/system_ui/MD_jp.gtx.p1.json&p=3，收藏/分享即可直达某一页。
    • 未翻译的句子显示灰色「未翻译」，可以直接在行内填入译文。
    • 行内编辑只替换上游 JSONL 里那一行的 zh 字段，其余字节不动；提交前先核对日文源文 hash，源文变了就拒绝写入。
    • 图片走公开对象存储直接外链（清单里给的是绝对地址）；打不开时显示占位，不伪造。
