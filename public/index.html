📦 独立版本发布与跨版本复用模型

🛡️

解耦发布规范 (Client / Assets Fully Decoupled)

客户端 APK 与资源包采用完全解耦的双发布轴： Client 仅针对 arm64-v8a 单一架构，仅绑定 APK 内置汉化资源与基础 APK SHA-256； Assets 由本地服务器在握手阶段通过 server_schema_version 进行契约协商下发，禁止跨版本版本号合成字符串。

📱 Client 客户端发布

严格约束: arm64-v8a

📦 Assets 资源发布

基准版本: 1077100

🔄 跨版本翻译复用四态机制 (Cross-Version Translation Reuse)

所有多版本资源基于 (logical_key, resource_kind, locale, source_sha256) 唯一逻辑键跨版本流通，杜绝机械重复翻译。

Exact

精确一致复用

源文本 SHA-256 完全相同，自动直接复用，不产生新翻译任务。

🔀 提案与 Pull Request

本页只展示提案与 PR 状态：审核权威是 GitHub Pull Request 自身，合并即在 GitHub 完成。 门户不在此接受译文、不回填，也不镜像一份独立的审核结论。

🔀 仓库 / 版本 / 资源选择

两个通道是相互独立的发布轴：Assets 走服务器下发通道，Client 走 APK 内置通道。 选定版本后选择条目，门户向服务读取该条目的提交绑定（目标仓库、路径、基线 commit）， 再交给工作台编辑；编辑只会改写该条目标所对应的那一行/槽位，并由 Pull Request 审核。

📖 翻译规范

提交前请过一遍

🚨 严禁半角 | 与 ^

译文出现半角 | 或 ^ 会导致游戏闪退，必须替换为全角。

❌ 严禁： | 和 ^
✅ 改用： ｜ 与 ＾
💡 输入框上方有 [🔄 修复符号] 按钮可一键替换。

🏷️ 标签与变量

只翻译文字，标签与变量原样保留：

<color=#HEX>...</color> 颜色标签

成对保留，只翻译中间文字。

日文：<color=#ea5b76>未来ちゃん</color>、頑張って！
译文：<color=#ea5b76>未来酱</color>，加油！
{$P$} 制作人昵称

代表玩家昵称，不可删除。

日文：{$P$}さん、お疲れ様です！
译文：{$P$}先生，辛苦了！ 或 制作人，辛苦了！
{0} / {1} / %s 参数占位符

原样保留，可调整语序。

日文：{0}個のジュエルを獲得しました！
译文：获得了{0}个群星宝石！
\n 换行

原文换行处对应换行，避免文字溢出。

日文：今日はとっても楽しかったね。\nまた明日も会おうね！
译文：今天真的非常开心呢。\n明天也要再见哦！

✍️ 标点习惯

  • 全角标点：使用 ，。！？……～，不用半角 ,.!?
  • 省略号与波浪号：日文 … 用 ……；〜 用 ～。
  • 译名统一：偶像名与系统词参考规范（如：艾米莉·斯图亚特、篠宫可怜、白石䌷、群星宝石）。
